# Voice Migration — Pre-generated Audio

Replaces runtime `speechSynthesis` with pre-generated MP3s played through
AudioContext. Fixes the iOS PWA standalone bug and upgrades voice quality on
every platform.

## Decision

| Setting | Value |
|---|---|

| Voice | **Jessica** — `cgSgspJ2msm6clMCkdW9` (playful, bright, warm) |
| Model | `eleven_multilingual_v2` |
| Settings | `stability 0.45`, `similarity_boost 0.75`, `style 0.15`, `use_speaker_boost true` |
| Format | `mp3_44100_64` — 188 clips, 3.1MB (128k was 5.7MB, no audible difference) |

Auditioned against Bella and Alice on 2026-08-17. Cost measured: 549 characters
for 18 clips. Per-family runtime generation is under 2,000 characters.

## Key idea: one lookup path

Every spoken line resolves through a single function:

```
audioKey(text) = sha1(text.trim().replace(/\s+/g, ' '))
```

Playback checks three tiers in order:

1. **Bundled** — `public/audio/<key>.mp3`, listed in a build-time manifest,
   precached by the service worker. Ships with the app.
2. **IndexedDB** — blob cached from a previous generation. Offline-safe.
3. **Server** — fetch from the cPanel endpoint, store in IndexedDB, play.

Static and dynamic clips are the same thing at different tiers. No branching in
call sites; `speak(text)` keeps its current signature.

## Tier 1 — bundled (build time)

Roughly 100 clips, ~2MB. Generated by a script, committed to `public/audio/`.

- 26 × `This is the letter X`
- 26 × `The letter X, is for <DEFAULT_WORD>` (defaults from `db.ts:107`)
- 26 × `Can you find the letter X?`
- ~12 × namegame position lines (`It's the Nth letter in your name`)
- ~10 × globals: greetings, `That's correct!`, `That's not quite right...`,
  round-complete, final congratulations

## Tier 3 — server-generated

Two sources of user-authored text:

- **Letter words** — parent edits `word` on a letter (`manage/page.tsx:66`).
  Generates the full phrase `The letter G, is for Grandma.`
- **Child name** — ~21 name-bearing praise + namegame phrases, once at setup.
- **Word bank** — custom words for the Word Learning game.

Full phrases, never spliced. A word costs ~8 characters vs ~28 for the phrase;
both are effectively free, and full phrases carry correct prosody.

### Endpoint contract (cPanel, beside the activation checker)

```
POST /api/tts.php
  { "text": "The letter G, is for Grandma.", "code": "<activation code>" }
  -> 200 audio/mpeg   (binary)
  -> 400 invalid text | 403 bad code | 429 rate limited | 502 upstream
```

Server behaviour:
1. Validate activation code — this is a paid-user-only endpoint.
2. Validate `text` against a **template whitelist** (letter-word phrase, known
   praise templates, single word-bank word). Reject anything else.
3. Cap length at 120 chars.
4. `sha1` the normalized text; serve `cache/<sha1>.mp3` if present.
5. On miss, call ElevenLabs, write to cache, serve.

The whitelist + activation gate matter: an open proxy is a way to burn the
ElevenLabs balance. The disk cache is also shared across all families, so
common words (Mommy, Daddy, Grandma) generate exactly once, ever.

### Pre-seeding

Bake the ~150 most common family words into tier 1 as full phrases (`M is for
Mommy`, `G is for Grandma`, ...). Most photo saves then need no network at all.

## Client rules

- **Never block the save.** Photo saves succeed immediately; audio generates in
  the background, retried on next launch. Mark the letter `audioPending`.
- **Never go silent.** Missing audio for a word plays the carrier alone
  (`This is the letter G`) rather than a gap or half-sentence.
- **Delete the speechSynthesis path entirely** once this lands — including the
  Chrome keep-alive hack and the mobile warmup utterance. One code path.

## CONFIRMED — on-device results

Tested on iPhone in standalone mode (`standalone=true` throughout), 2026-08-17,
via `tools/audiotest/`. Everything below is measured, not assumed.

### 1. speechSynthesis is dead in standalone

Every attempt logged `RESULT speechSynthesis SILENT (onstart never fired)`.
No error, no callback, no sound. The WebKit bug is confirmed and the
speechSynthesis path should be deleted outright.

### 2. AudioContext buffers work — after one gesture

The context is created `suspended` on every page load. After a single tap,
`resume()` moves it to `running` and clips play reliably: verified at 1.4s,
9.7s, 56.3s and 77.7s into the context lifetime, all `RESULT PLAYED`.

**One gesture unlocks the page for its entire lifetime.** Games can speak
autonomously after the gate. This was the assumption the migration rested on,
and it holds.

### 3. Navigation destroys the unlock

Every full page load creates a fresh `suspended` context. The gate belongs on
*every* game page, not just the entry point.

### 4. TRAP — resume() does not reject, it defers

The most important finding, and not what was expected.

Calling `resume()` without a gesture does not fail. The promise stays pending
until a gesture eventually arrives — measured at **15.7 seconds** in one run
(requested 19:53:55.720, resolved 19:54:11.426, immediately after the tap).

When it resolves, the queued audio fires. In the page-2 runs this played
**two clips on top of each other, 6ms apart**: the deferred auto-greeting and
the clip the user had actually tapped for.

Real consequence: a game that speaks on mount, then waits while a child taps a
letter ten seconds later, plays the greeting and the letter sound at once.

**Rule: never issue a play call while `ctx.state !== 'running'`.** Check state
explicitly and drop or hold the request. `await resume()` is not a gate.

### Required changes

- Tap-to-start gate on all 8 game modes and any page that speaks on mount
- `speak()` no-ops unless `ctx.state === 'running'` — never relies on resume()
- Discard pending audio on navigation
- Re-check context state on `visibilitychange` (untested; a child locking the
  screen mid-game is routine and may suspend the context)

## Numbers corpus — added 2026-08-30

The Numbers modes add **74 clips** to the bundled tier (262 phrases total, 188
already generated). Every counting phrase is fixed text, so all of it is tier 1
and `server/tts.php` needs no new whitelist pattern — the one personalized line,
`Hi <name>! Let's count!`, already matches the existing
`Hi .{1,30}! Let's .{1,40}` rule.

| Group | Count |
|---|---|
| Count beats `One.` … `Ten.` | 10 |
| Cardinality recaps `Three! There are three.` | 10 |
| Whole sequences `One, two, three.` | 9 |
| `This is the number N` | 10 |
| `Can you find the number N?` | 10 |
| `You pressed the number N!` | 10 |
| Prompts, level announcements | 15 |

Canonical text lives in `src/lib/countingPhrases.ts` and is **mirrored** by
`countingCorpus()` in `scripts/generate-audio.mjs`, the same convention the
letter phrases already use. Change one, change both, then re-run the generator.

### To generate them

```bash
ELEVENLABS_API_KEY=... node scripts/generate-audio.mjs
```

Idempotent — it skips the 188 existing clips and writes only the 74 new ones,
then regenerates `src/lib/audioManifest.ts`. Until that runs, the Numbers modes
play silently: `speak()` finds no bundled key, the server rejects the phrase,
and the game continues without audio rather than failing.

`public/sw.js` is already bumped to `myalphapics-v5` so `warmAudioCache()`
re-warms against the larger manifest on the next service worker activation.

### Counting cadence

Ten separately generated clips played back to back would sound like a list, not
a count. The resolution is that **the child supplies the rhythm**: in tap-to-count
each number sits on its own beat, separated by however long the child takes, so a
flat evenly-stressed `One.` is correct there. The whole-sequence clips exist for
Count With Me, where the app counts on its own and needs real prosody — full
phrases, never spliced, same rule as the letter phrases.
